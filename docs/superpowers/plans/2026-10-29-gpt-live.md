# GPT-Live host bridge implementation plan

> **For agentic workers:** Use the existing inline execution method. Keep all work local, preserve the October 25 changes, and do not commit, deploy, configure secrets, call a paid API, or flash.

**Goal:** Implement and mock-test the feasible host portion of GPT-Live while retaining Hermes backend orchestration.

**Architecture:** A bounded session state machine and asynchronous audio/event pump use GPT-Live client delegation. A separate adapter sends delegated context through Pocket's existing durable ChatService, preserving task history and uncertain-admission handling.

**Tech Stack:** Python standard library; caller-supplied OpenAI SDK with Live support at future deployment time.

**Spec:** `docs/superpowers/specs/2026-10-29-gpt-live-design.md`.

## Global constraints

- Exact voice model `gpt-live-1`; no Realtime fallback.
- Raw mono PCM16 at 24 kHz; caller paces microphone data. Do not feed current 16 kHz device bytes unchanged.
- Five-minute default session lifetime; bounded startup/close, transcript, delegation and playback queues.
- Credentials remain outside this implementation and test data. No real client or service is constructed during tests.
- Current push-to-talk firmware/server remains unchanged; full-duplex device acceptance and the prior release gate remain open.

## Review focus

- A delegation event has no utterance: use timestamped transcript context and reject missing/future-only context.
- Duplicate or uncertain work must never be resubmitted automatically.
- Pending approval is not success and must not be approved by the voice bridge.
- Slow backend/playback must not stop microphone handling or create an unbounded queue.
- Disconnect or interruption must not be reported as backend cancellation or completed playback.

## Task 1: Bounded Live session and transport

Create `pocket/gpt_live.py`; test with `tests/test_gpt_live.py`.

Interfaces: `LiveSettings`, `LiveSession`, `LiveError`, `run_connection(connection, backend, microphone, playback, stop, settings=...)`, and `run_gpt_live(client, ...)`. The connection sends documented JSON events and asynchronously yields server event dictionaries; the SDK wrapper adapts documented Live helper methods.
